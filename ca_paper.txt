Abstract
This report presents a comprehensive microarchitectural analysis of Level 1 (L1) Data Cache
dynamics using the Gem5 simulator. We evaluated the impact of cache capacity, workload
memory access patterns (Matrix Multiplication vs. AES Cryptography), and cache associativity
on an X86-basedTimingSimpleCPU. The results demonstrate that increasing capacity from
4kB to 64kB reduces capacity misses from 5.06% to 0.04% for linear algebraic workloads,
while cryptographic payloads remain indifferent to capacity scaling. Furthermore, an evaluation
of mapping schemes at a constrained 16kB capacity revealed that increasing associativity from
Direct-Mapped to 8-Way Set-Associative effectively mitigates conflict misses, improving IPC
by 10.4%.
Keywords:Gem5 Simulator, Cache Memory, IPC, Miss Rate, Associativity, AES, Matrix Mul-
tiplication, X86 Architecture.

1 Literature Survey
Modern processors are critically bottlenecked by the ”Memory Wall,” requiring sophisticated
cache hierarchies to maintain data throughput.
•Miss Classifications:Cache inefficiencies are broadly categorized into the ”Three C’s”:
Compulsory, Capacity, and Conflict misses. Architectural design aims to balance silicon
area and latency to address these bottlenecks [1].
•Workload Diversity:Programs exhibit varying degrees of temporal and spatial locality.
Linear algebraic kernels heavily utilize spatial locality, while cryptographic algorithms
(like AES S-Box lookups) frequently present non-linear, scattered access patterns [2].
•Simulation Tools:The Gem5 simulator provides cycle-accurate models of CPU pipelines
and memory subsystems, enabling precise evaluation of hardware-software co-design
without physical fabrication [3].
2 Limitations of Available Technology
In resource-constrained environments such as embedded IoT devices and UA V flight controllers,
hardware cannot be dynamically resized.
•Thrashing and Conflicts:Fixed, Direct-Mapped caches suffer from severe conflict misses
when executing matrix-heavy operations (e.g., sensor fusion), leading to pipeline stalls.
•Power Constraints:While highly associative caches (e.g., 8-Way) eliminate conflict
misses, they require complex, power-hungry multiplexing logic, making them unviable
for ultra-low-power edge nodes.
3 Proposed Methodology
The experiments were conducted using Gem5 (Version 25.1) simulating an X86TimingSimpleCPU.
1.Capacity Experiment:Executed a 100x100 Matrix Multiplication C-benchmark (work-
ing set≈40kB). The L1 Data cache was varied across 4kB, 32kB, and 64kB (Default
Associativity).
2.Workload Sensitivity:Executed an AES SubBytes benchmark (150kB payload) across
the same capacities to contrast memory access behavior.
3.Associativity Experiment:The matrix benchmark was executed with the L1 Data cache
locked at 16kB. The mapping scheme was varied across 1-Way (Direct-Mapped), 2-Way,
and 8-Way Set-Associativity.

6 Analysis of Obtained Results
1. Mitigating Capacity Misses:In Experiment 1, the 4kB cache thrashing yielded a 5.06%
miss rate because it was smaller than the 40kB working set. Expanding the cache to 64kB
captured the entire set, dropping misses to a negligible 0.04% (purely compulsory misses).
2. Algorithmic Sensitivity:Experiment 2 revealed that lightweight cryptographic work-
loads behave differently. Because the AES S-Box is only 256 bytes, it fits entirely within the
smallest 4kB cache. The scattered, non-linear lookups and linear payload streaming resulted
in a static 0.14% miss rate, proving that simply adding cache memory does not solve pipeline
execution bottlenecks for all algorithms.

3. Mitigating Conflict Misses:In Experiment 3, constraining the cache to 16kB forced
contention. Under a Direct-Mapped (1-Way) scheme, the 4.74% miss rate heavily restricted the
IPC. Transitioning to a 2-Way set-associative layout halved the miss rate to 2.07%, confirming
the elimination of severe conflict misses. The 8-way scheme provided diminishing returns
(0.34% misses), demonstrating the classic architectural trade-off between associativity benefits
and hardware complexity.
7 Conclusion
This study validates that cache optimization requires a holistic view of the targeted workload.
While data-heavy linear algorithms benefit exponentially from larger capacities and flexible as-
sociativity mappings to prevent conflict and capacity misses, specialized edge workloads like
cryptography are bottlenecked elsewhere. Optimizing hardware for UA Vs or IoT devices re-
quires tailoring the cache hierarchy—such as utilizing highly-associative, smaller caches for
dense matrices—rather than relying on brute-force capacity expansion.
